# Windows 0.3.3 账号输入修复与验证

日期：2026-10-24（Asia/Shanghai）。

## 原因与修复

账号、密码和备注原先绑定 `enabled: !busy`，自动检测每轮开始时会禁用字段并中断输入。添加账号、账号详情切换和密码显示也使用全局忙碌拦截，影响本地编辑。

控制器现在独立提供 `configurationBusy`，仅在配置任务执行期间锁定本地编辑。普通网络检测、认证与状态通知不会锁定字段，编辑中的草稿、焦点和输入法状态保留。保存、删除、选用账号继续沿用全局忙碌保护与串行执行器，避免并行修改凭据。保存按钮在网络任务结束后可用。

## 验证

- 修复前，新增真实 QML 回归检查复现“检测期间无法打开添加账号”；修复后通过。
- 实际发送键盘事件，检测忙碌/空闲切换间持续输入账号、密码及备注，核对文字、光标和焦点。
- 发送中文输入法预编辑与提交事件，核对检测开始时组合文字仍保留并可完成输入。
- 配置写入期间字段锁定，任务结束后恢复；控制器单元测试覆盖真实执行器的网络任务与配置任务区分。
- 桌面单元测试 109 项、CLI/发布工具测试 47 项通过，真实 QML 交互检查通过且无 QML 警告。
- 构建脚本还执行源码 QML、独立 EXE 环境检查、安装器及完整免安装 ZIP 打包。具体结果记录在本地 `desktop/build-input-fix.log`、`desktop/screenshots/v0.3-ui/ui-report.json` 与 `desktop/.cache/clean-runtime-report.json`。

界面检查使用模拟账号、离屏 Qt 软件渲染，不连接校园网或读取用户真实凭据。中文输入使用 Qt 输入法事件模拟，真实 Windows 输入法人工操作仍需试用确认。本次不自动覆盖现有安装或公开 GitHub Release。
