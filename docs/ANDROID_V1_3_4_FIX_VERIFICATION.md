# OUNet Android 1.3.4 实施与验证

日期：2026-10-23。versionCode 8，保留原包名、正式签名、OUNet名称与图标。

## 原因与新流程

1.3.3每轮先识别XHA，再通过配置发现与chkstatus确认会话，最后才检查外网。账号详情缓存只减少详情请求，不能阻止前面的状态读取链。因此外网持续可用，仍会反复出现“认证服务可用→读取登录状态→账号已确认→外网通过”的日志和XHA调用。

1.3.4在LoginEngine中将实际Wi-Fi的外网探测移到上述链路之前：

1. 启动、账号切换、自动监测、普通复检先轮换公共服务验证外网。
2. 通过则发布“外网验证通过”并结束本轮；不调用校园识别、状态读取、认证及详情刷新。相同状态不会持续重复追加诊断日志。
3. 外网不可用才走XHA识别和原有按需认证。没有系统认证页证据时，单个服务失败先换服务复核；等待公共探测的300毫秒合并窗口也不触发XHA请求。
4. 用户明确点击“重新检测并连接”仍执行强制XHA刷新和失败保护重置。账号信息“刷新”、设备列表操作也是用户主动请求，不受健康监测短路影响。

外网优先检查每轮要求真实探测，不使用原15秒在线结果缓存；公共请求仍共享300毫秒最小派发间隔，并轮换Microsoft、Apple、Mozilla。没有新增认证冷却或XHA分钟限额。实际调度受请求耗时及Android后台限制影响。

## 界面与信息保留

同一Wi-Fi、同一配置下保留上次读取的账号及六字段，显示XHA读取时间；即使详情缓存超过5分钟，健康监测也不自动刷新。切换Wi-Fi或配置后清除不匹配的信息。首次外网正常但未查询过XHA时显示“尚未读取”及手动刷新说明，不声称已核实校园身份。

密码错误保护继续保留；检测到外网自行复通时显示联网状态并隐藏旧错误面板，不再次提交密码。没有XHA认证成功证据时不删除已保存的凭据错误，后续真正断网仍保护同一组错误凭据。
