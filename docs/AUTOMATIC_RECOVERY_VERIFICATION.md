# Android与Windows自动恢复设计及验证

日期：2026-10-24。版本：Android 1.3.6 / code 10；Windows 0.3.4。

## 行为

临时故障达到三次后进入冷却，到期允许一个串行恢复流程。等待依次为15、30、60、120、300秒，再失败继续300秒，不设置永久失败次数上限。复检先确认外网与XHA状态，只有确认未登录才认证。已恢复外网、确认XHA在线或认证成功会清除对应临时故障并继续正常守护；普通状态HTTP成功不会清除独立登录失败计数。

网络事件可提前复检一次，重复事件至少间隔15秒，不依赖事件才能恢复。Windows使用Qt单次定时器，Android使用前台服务及原有合并调度；Android锁屏和后台执行时间受系统约束。

明确账号密码错误仍绑定账号/凭据，不能被定时器、网络事件或外网恢复清除。用户关闭守护后不安排自动认证，主动连接仍可执行。Windows旧入口安全暂停与本地状态损坏不自动放行，TLS校验与实际接口绑定保持。

## 存储与迁移

- Windows保留`request-state.json`及凭据错误，添加可选冷却级别和下次复检时间。普通旧暂停转为15秒冷却，`legacy_pause`保留。外网、GitHub更新、登录结果使用独立`request-state-*.json`，仅记录必要状态，不保存明文密码。
- Android原`retry`版本2升级为版本3，保留失败记录并添加级别、下次时间；XHA连通性另存`transport_retry`。升级不改账号密文、Keystore、包名与签名。时间回拨时剩余等待限制在当前级别上限，并重新保存锚点。
- Windows运行期间使用单调时钟，跨重启用持久化时间恢复且限制剩余等待上限。存储写入失败不授予自动请求权限。

## 自动验证

本轮结果：Android 163项单元测试通过，Lint无问题；Windows 121项桌面测试、47项CLI/发布工具测试通过。真实QML检查无警告，冻结EXE在清除开发环境路径后通过QML、DPAPI和TLS检查。正式APK已核对原签名，两端安装包和发布元数据的SHA-256校验通过。

覆盖冷却前零额外请求、到期只试一次、连续失败逐级等待并封顶、无网络事件恢复、重启保留截止时间、旧状态升级、时间回拨、重复网络事件合并、外网/XHA/更新隔离、密码错误保留和关闭守护不认证。

Windows还执行真实QML键盘与中文输入法检查，核对自动检测和冷却状态不打断账号输入，保留按钮样式与焦点。构建脚本执行完整单元测试、源码QML、独立EXE环境检查、安装器及完整ZIP打包。

Android使用Robolectric模拟Wi-Fi与HTTP，覆盖路由器不可达三次、恢复后自动认证、登录拒绝后单次半开试登以及恢复外网时保留密码错误。构建执行单元测试、Lint、正式APK打包、原签名与SHA-256核验。

本地报告：`desktop/tests-recovery.log`、`desktop/ui-recovery.log`、`desktop/build-recovery.log`、`android-build-recovery.log`以及Android测试XML。所有自动检查使用模拟网络、临时数据，不访问真实校园认证或覆盖用户现有安装。
