## 1. 产品定位

工作名称为“海大网络助手”。面向需要长期使用中国海洋大学校园网的个人 Windows 用户：首次设置账号和目标 Wi-Fi 后，平时留在系统托盘，有网络时安静待命，需要认证时帮助恢复连接。

核心价值是减少手动输入和排障成本，同时限制重复认证。产品应让用户随时知道“现在有没有网络、自动守护是否运行、为什么没有继续尝试、下一步能做什么”。

学校元素用于建立熟悉感，整体保持独立工具身份。品牌素材、界面视觉和来源以本次设计交付为准；不得把软件介绍为学校官方客户端，也不在安装包中嵌入任何真实账号密码。

### 1.1 面向的使用场景

| 场景 | 产品应做到 |
| --- | --- |
| 每天登录 Windows | 根据用户设置在后台启动，无命令行黑框，不反复打开主窗口 |
| 校园 Wi-Fi 认证失效 | 确认无外网且处于目标网络后，尝试认证并复查 |
| 电脑锁屏或主窗口关闭 | 用户会话仍在时继续守护；主窗口关闭收起至托盘 |
| 账号错误、服务器故障 | 显示原因与失败保护，不无限重复登录 |
| 临时使用其他 Wi-Fi 或有线网络 | 有网不认证；不未经设置切走正在使用的 Wi-Fi |
| 从旧脚本迁移 | 导入配置和保护状态，引导停用旧任务，避免两套自动化并行 |

### 1.2 产品承诺与边界

- 只有网络检查表明外网不可用，才考虑校园网认证。
- 普通操作不提供“已联网仍强制登录”的捷径。
- 自动流程与手动流程共享认证预算、运行锁和状态。
- 不通过注销已有会话来强制登录，不自动绕过证书校验。
- “已联网”表示实际探测到外网可用；“认证服务器返回成功”仍需要后续验证。
- 初版支持登录 Windows 后运行。未登录、注销、关机和睡眠期间，不承诺执行检测。

## 2. 功能范围

### 2.1 MVP：长期个人使用所需的完整闭环

| 功能 | MVP 设计 |

| 安装与卸载 | 用户级 EXE 安装器，开始菜单入口、卸载入口，安装后无需自行配置 Python |

### 2.2 P1：首版稳定后再增加

- 多个已授权目标 Wi-Fi 的配置与优先级。
- 更完善的网络变化监听、以太网与多网卡诊断。

- 深色模式、更多字号与无障碍细节。

### 2.3 本轮不做

## 3. 信息架构

主窗口建议分为五个页面，常用操作留在首页，协议参数留在诊断中。

| 页面 | 内容 | 主要操作 |
| --- | --- | --- |
| 连接概览 | 大号状态、当前 Wi-Fi、守护状态、最近检查、保护提示、最近活动摘要 | 检查并连接、暂停/恢复守护 |
| 账号与网络 | 账号、密码是否已保存、目标 Wi-Fi、Windows 保存的配置 | 保存设置、选择目标网络 |
| 活动记录 | 检查、认证、保护、配置变更的可读记录 | 筛选、导出脱敏诊断 |
| 偏好设置 | 登录后自启、2 分钟间隔、通知、关闭行为、重置保护 | 调整偏好、查看说明 |
| 帮助与关于 | 故障问答、版本、个人工具身份、学校元素来源 | 查看帮助和来源 |

首次向导只在未完成设置时出现。主界面不反复展示长篇说明，不以动态计数或“修复成功次数”制造不必要的操作动机。

### 3.1 首页的展示优先级

1. 当前网络是否可用，以及当前是否正在检查。
2. 如需操作，明确显示原因和一个主要动作。
3. 自动守护开关及“后台运行 / 用户已暂停 / 认证保护暂停”的解释。
4. 网络名称、上次检查、最近活动等次要信息。

不要仅用颜色表达状态。图标、标题、说明文字共同呈现；网络异常和失败保护不能都只显示模糊的红色“连接失败”。

## 4. 状态模型与界面矩阵

网络可用性、守护开关和认证保护是独立维度。例如：外网不可用、自动守护开启、认证保护暂停可以同时成立。界面应呈现组合状态，不能把所有信息塞进一个开关。

| 状态 | 用户看到的说明 | 是否允许认证 | 主要操作 |
| --- | --- | --- | --- |
| 未完成设置 | 请先保存校园网账号和目标 Wi-Fi | 否 | 完成设置 |
| 检查中 | 正在确认外网连接 | 暂不新增流程 | 显示进度；合并重复点击 |
| 已联网 | 外网可用，本轮无需认证 | 否 | 可再次检查，保持不认证 |
| 目标 Wi-Fi 未连接 | 当前不在设置的无线网络上 | 否 | 连接目标 Wi-Fi / 打开 Windows 网络设置 |
| 目标 Wi-Fi 不可用 | 未找到已保存配置或无法连接 | 否 | 检查网络设置 |
| 准备认证 | 外网不可用，正在读取认证配置 | 已获得本轮预算后允许 | 展示当前阶段 |
| 正在恢复 | 已提交认证，正在复查外网 | 不并行启动新认证 | 等待当前流程 |
| 本轮未恢复 | 显示原因与最近失败轮次，例如 1/3 | 受间隔与预算限制 | 查看说明 / 等待下一轮 |
| 失败保护暂停 | 10 分钟内连续 3 轮未恢复，已暂停认证 | 否，且不读取认证配置 | 修改设置 / 手动重置保护 |
| 用户暂停守护 | 自动检查已暂停 | 仅手动检查可触发，仍受保护限制 | 恢复守护 / 手动检查 |
| 保护状态异常 | 无法读取或保存保护状态，为避免重复请求已停止认证 | 否 | 打开诊断说明 |
| Wi-Fi 权限异常 | 无法确认目标 Wi-Fi，请检查位置权限或 WLAN 服务 | 否 | 打开对应系统设置说明 |

“上次已联网”是历史记录。检测中或结果过旧时不继续冒充实时在线状态。“已联网”也不能直接写为“校园 Wi-Fi 已认证”，因为电脑可能通过有线网络或其他出口联网。

### 4.1 通知和托盘

托盘使用在线、恢复中、等待处理、已暂停等可区分状态；悬停提示同时写出文字。双击托盘打开已有主窗口，再次启动程序只唤起已有实例。

通知拟定规则：首次触发失败保护、需要用户处理配置/权限、一次故障后恢复网络时通知。一直联网、周期检查和同一个未处理错误不重复通知；用户可关闭恢复通知。

关闭主窗口默认收起至托盘，第一次解释一次该行为。“退出”明确停止本进程守护；若登录后自启仍开启，下次登录会重新运行。用户在界面选择暂停自动守护时，暂停偏好应保存，重启后不偷偷恢复。

## 5. 核心流程

### 5.1 安装与首次配置

1. 用户运行安装包，完成按当前用户安装。
2. 打开首次向导，选择 Windows 已保存的目标 Wi-Fi；未保存时引导到系统设置手动连接一次。
3. 输入校园网账号和密码，明确说明其与 Wi-Fi 密码不同。
4. 保存到当前用户的安全存储，执行一次“检查并连接”。
5. 无论电脑当前是否通过目标 Wi-Fi 联网，只要外网正常就跳过认证。
6. 用户选择是否登录后自动运行、是否允许自动连接目标 Wi-Fi；完成后进入概览。

安装完成不自动提交认证。首次连接由清楚的用户操作发起；之后的自动守护使用已保存设置。

### 5.2 正常检查和断网恢复

```text
周期 / 网络事件 / 用户点击
          ↓
合并触发，检查是否已有一轮执行
          ↓
检查外网 ── 可用 → 清除失败保护，更新在线状态，结束
          ↓ 不可用
检查认证保护 ── 已暂停 / 状态异常 → 显示说明，结束
          ↓ 允许继续
确认目标 Wi-Fi ── 不满足 → 根据设置连接或提示用户，结束/继续
          ↓
再次检查外网 ── 已恢复 → 清除保护，结束
          ↓
确认认证间隔与预算，先持久化本轮占用
          ↓
读取认证页、脚本、配置，按受支持的协议提交
          ↓
复查外网 ── 可用 → 清除保护，显示恢复成功
          ↓ 仍不可用
记录本轮未恢复，达到上限则保持认证暂停
```

HTTPS 证书校验失败、认证方式不支持或状态存储异常时停止该流程，并展示具体阶段。不得临时降级明文 HTTP、猜测接口或先注销账号。

### 5.3 检测节奏与请求合并

拟定桌面版默认每 **2 分钟**执行一轮外网检查。网络切换、从睡眠恢复等事件先等待约 5 秒稳定，再合并成一次检查；程序已有检查时只保留一个待检查标记，避免并行调用。

网络事件不会绕过认证间隔和失败预算。自动认证轮次之间拟定至少间隔 2 分钟；手动点击可以检查外网，但若认证仍处于间隔限制中，应显示预计等待时间，不立即再提交。所有入口均通过统一调度器处理。

外网探测继续检查预期响应内容，不能仅凭 HTTP 200 判断成功，也不能仅依赖 Windows 的网络图标。探测只说明电脑当前外网可用性；首页遵循用户既有规则“电脑已有网络就不登录”。如后续增加“只检查校园 Wi-Fi”的模式，需另行设计网卡绑定和提示。

### 5.4 失败保护及恢复

保留现有设计：默认 **10 分钟内连续 3 轮认证后仍未恢复外网，就暂停校园网认证请求**。

这里的“一轮”指认证流程，不是一个 GET。一轮可能包含认证页面、脚本、配置、提交登录等最多 4 个校园网请求；所以界面不能承诺“最多只向服务器发送 3 个请求”。连接 Wi-Fi 失败且尚未开始认证时不占用轮次。

例如在 11:00、11:02、11:04 开始的三轮都未恢复网络，第三轮结束后维持保护暂停。**10 分钟不是自动解禁倒计时**；即使到了 11:20、重启电脑或退出再打开，也不自动认证。

暂停期间仍可检查外网，但不读取校园网认证页、脚本、配置或提交登录。只有以下两种方式解除：

- 实际检测到外网恢复，自动清零；保持现有“电脑外网可用即恢复”的语义。
- 用户明确点击“重置失败保护”。操作说明重新开放认证预算，本身不发网络请求；随后可另行点击“检查并连接”。

保存新密码、点击刷新、切换页面、重新开关自动守护、普通诊断和应用升级，都不得隐式清零。某一轮已获得预算后被终止时，保守保留该次占用；第三轮在获得最后一个预算后可完成，其他入口从此不能再取得预算。

## 6. 从脚本到桌面应用的迁移

现有脚本的配置、日志、失败状态和锁都位于源码目录。打包后不能继续把可写状态放在安装目录，也不能简单复制程序而开启一套新的独立预算。

### 6.1 拟定目录

| 数据 | 拟定位置与要求 |
| --- | --- |
| 程序文件 | 用户级应用安装目录；不保存凭据、运行日志或动态状态 |
| 非敏感设置 | `%LOCALAPPDATA%\OUCNetworkAssistant\settings.json` |
| 加密凭据 | `%LOCALAPPDATA%\OUCNetworkAssistant\credentials.dat`；使用当前用户 DPAPI |
| 失败保护 | `%LOCALAPPDATA%\OUCNetworkAssistant\retry-state.json`；原子写入并带版本号 |
| 活动日志 | `%LOCALAPPDATA%\OUCNetworkAssistant\logs\`；轮转、限制大小 |
| 导出报告 | 用户明确选择的位置；默认脱敏，不含凭据 |

目录名是实现建议，实际编码时统一定义，不分散硬编码。当前用户目录的 ACL 与 DPAPI 一起使用；禁止使用让本机所有用户均可解密的机器级 DPAPI 标志。

### 6.2 旧配置和任务计划

首次向导提供“导入现有脚本配置”，明确选择项目目录或 `.env`。只在本地读取，不上传；导入凭据后加密保存。原明文文件是否删除由用户明确决定，界面说明残留位置。

迁移同时读取 `.login_retry_state.json`：已暂停则继续暂停，未暂停的有效轮次保留，损坏时以停止认证的状态进入诊断。不能因导入账号或重新安装获得新的无限重试机会。

迁移页检查可识别的旧任务和进程，展示名称、操作命令、是否匹配本项目路径。用户明确选择后才停用匹配任务；不处理无法确认来源的其他任务。**本轮规划和原型不修改任何真实任务计划。**

### 6.3 多进程和兼容性

新桌面程序使用当前用户范围的命名互斥锁：重复启动只激活已有窗口；检查、诊断、手动重置与定时器共用一条执行队列。

如果继续支持命令行，新旧入口需升级到相同状态目录、锁和预算服务。未修改的旧脚本仍使用源码目录锁，无法靠新程序单方面保证共享限制。因此，在完成旧任务停用或兼容升级前，不应开启新的自动守护；展示迁移待完成状态并允许用户继续手动使用原工具。

## 7. 技术路线

### 7.1 推荐方案

**Python 核心 + PySide6 + Qt Quick/QML 界面 + 用户级安装器。** 该方案复用现有认证、错误处理和失败预算，减少同时重写协议与桌面体验的风险。Qt 提供 [系统托盘 API](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html)，其官方部署指南列出冻结为可执行文件与安装器等分发方式，并推荐自带部署工具作为选项。[Qt 官方部署指南](https://doc.qt.io/qtforpython-6/deployment/index.html)

拟定模块：

```text
QML 界面 / 托盘
       ↓ 状态订阅与明确命令
MonitorController：调度、状态机、事件合并、单次流程
       ├─ ConnectivityProbe：外网探测
       ├─ WifiAdapter：读取与连接已保存网络
       ├─ PortalClient：配置发现、认证、响应解释
       ├─ RetryGuard：持久化预算、暂停、显式重置
       ├─ CredentialStore：当前用户 DPAPI
       └─ EventLog：结构化、脱敏、轮转
```

网络与文件操作放在工作线程，UI 通过信号接收结构化结果；不在主线程运行 `requests`、`netsh` 或等待重连。停止自动守护意味着不再启动下一轮；已经提交到服务器的请求不能承诺撤回。

先将当前全局路径、日志和配置读取改为可注入依赖，保留命令行入口。界面不通过解析日志文字识别状态，认证模块也不直接操作界面控件。Windows Wi-Fi 接口适配应集中封装，便于后续从 `netsh` 过渡到系统 API。

### 7.2 打包、凭据和自启依据

- 可执行文件需携带 Python 与依赖，用户不用另装 Python。PyInstaller 官方说明支持这种独立分发，也提供无控制台窗口的构建方式；实际采用 PyInstaller 或 Qt 部署工具，在构建验证阶段确定。[PyInstaller 工作方式](https://pyinstaller.org/en/stable/operating-mode.html)
- 当前用户 DPAPI 通常要求同一用户凭据及同一电脑才能解密。它用于保护静态存储，不等于能够抵御当前用户会话内所有恶意程序，也不能作为可跨电脑复制的密码备份。[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)
- 拟采用 Inno Setup 按当前用户安装，配置 `PrivilegesRequired=lowest`，避免例行安装申请管理员权限；系统 Wi-Fi 权限失败另行给出说明，不默认把守护进程一直提权。[Inno Setup PrivilegesRequired](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)
- 登录后自启使用用户级启动机制，并允许用户关闭。Microsoft 说明 Run 项在用户登录时运行，系统可能延迟执行，因此产品文案写“登录后自动运行”，不承诺开机后立即运行。[Microsoft Run 与 RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)

发布前需检查所有打包组件的再分发许可与声明。产品不需要为了联网检测增加常驻本地 HTTP 服务器、云后端或额外账号体系。

## 8. 安装、升级与卸载

### 8.1 安装

- 采用固定应用标识、可辨认版本号和安装目录，创建开始菜单及卸载入口。
- 安装包不包含开发者 `.env`、原始日志、个人配置或真实保护状态。
- 用户明确选择登录后自启；后续可在偏好中调整。
- 普通启动无黑框，后台子进程也不弹控制台。
- 对外分发时规划代码签名，发布文件校验值；未取得签名不能宣称不会触发系统信誉提示。

### 8.2 升级

- 升级前让当前流程安全结束，避免两版并发认证。
- 保留设置、加密凭据、用户暂停偏好、失败预算和保护标记。
- 状态格式有版本号；迁移失败停止认证并显示错误，不清空后自动重试。
- 保持当前用户身份访问原凭据；不可因安装器提权切换到另一账户后重新保存凭据。
- 首版可通过下载安装包覆盖升级。自动更新属于后续功能，不能依赖联网更新才能恢复校园网络。

### 8.3 卸载

- 停止本软件进程，移除本软件自启项、开始菜单入口和程序文件。
- 明确让用户选择是否清除本地账号、设置和日志；不得顺带删除原脚本目录或无关任务。
- 如选择保留数据，保留失败保护；重新安装不能默认清零。
- 卸载最后说明是否仍有用户保留的旧脚本或任务，避免用户误以为所有联网自动化都已停止。

## 10. 验收标准

### 10.1 连接与请求控制

- 外网正常：周期检查、主按钮和登录后启动均不读取校园认证页或提交账号密码。
- 目标 Wi-Fi 断网：按真实配置完成认证并通过外网复查；仅服务器返回成功不提前报成功。
- 非目标 Wi-Fi：不提交凭据；未开启自动切换时不自行抢占当前网络。
- 三轮失败：第三轮后不再访问校园网认证页、脚本、配置及登录；等待超过 10 分钟、重启程序和电脑后仍受限。
- 恢复清零：外网探测确认恢复后解除保护；手动重置本身不产生校园网请求。
- 并发触发：网络事件、连续点击、定时器、第二个程序进程不会增加认证并发或绕过预算。
- 断网、协议变化、证书错误、状态文件损坏均显示具体原因，不降级安全策略。

### 10.2 Windows 体验

- 正常启动和周期检查不弹黑框，不需要每次管理员批准。
- 用户登录后按设置启动；锁屏保持运行，注销后停止；睡眠恢复后的事件被合并处理。
- 关闭主窗口继续托盘守护，“退出”停止守护，用户暂停偏好跨重启保留。
- 系统托盘不可用或自启被系统/用户禁用时，主界面不伪报功能已运行。
- 高 DPI、键盘操作、窗口缩放和文字放大时，主要按钮与保护提示保持可读。

### 10.3 安装与数据

- 未装 Python 的受支持 Windows 电脑可安装运行。
- 安装包、日志、导出报告和示例截图均不包含真实密码、完整认证 URL 或未遮挡个人账号。
- 导入旧配置同时保留失败状态；旧任务未处理时不会悄悄形成双重守护。
- 程序写入用户数据目录；升级保留凭据与预算；卸载只清理本软件明确拥有的数据。

以上为后续实现验收要求，并非本轮已经通过的测试结果。真实断网认证、学校服务器返回和不同 Windows 权限环境，需要在用户本机验证；交互原型的状态切换只能证明设计可审阅。

## 12. 长期维护与分发路径

当前先服务个人长期使用，再逐步扩大验证范围。建议按三个版本推进：

| 版本 | 对象 | 重点 |
| --- | --- | --- |
| 0.1 内测 | 当前用户本机 | 核心保护不退化、托盘安静运行、旧任务迁移、干净安装与覆盖升级 |
| 0.9 候选 | 少量自愿测试的同学 | 不同 Windows 版本、网卡、目标 Wi-Fi、权限环境；每个问题有脱敏复现记录 |
| 1.0 稳定 | 明确支持范围内的用户 | 发布说明、安装包签名方案、校验值、依赖声明、卸载、维护与问题反馈说明 |

个人版可通过本地安装包及项目 Releases 分发。原有 Python 工具保留为开发与排障入口；正式用户按清楚的版本说明安装，不需要自行管理运行环境。公开发布前确认学校元素的使用范围，并将个人工具身份写入安装器、关于页和发布页。

主要维护成本是 Portal 协议变化、Windows 网络权限变化、Qt 与打包依赖更新、安装器兼容性和签名费用。先通过小范围实际记录估计维护量；本规划不预设商业收入或未经测量的安装体积、资源占用。

发布质量以实际恢复结果、误触发认证、保护生效、升级保留状态、后台弹窗和用户排障成功率评估。初期用自愿反馈及本机脱敏诊断收集证据，不为这些指标额外建设云端账户或遥测服务。学校更新认证协议后，先在模拟响应和测试账号环境验证兼容，再发布更新；不能靠自动增大重试次数掩盖协议故障。
