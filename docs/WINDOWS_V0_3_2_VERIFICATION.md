# Windows 0.3.2 按钮闪烁修复与验证

日期：2026-10-24（Asia/Shanghai）。

## 修复原因与范围

原按钮把全局 `busy` 直接绑定到 `enabled`。每轮自动检测开始和结束都会改变按钮底色、文字颜色、悬停与焦点；主连接按钮还会反复显示“正在处理”。此外，状态通知复制的账号数组会令 Repeater 重建账号按钮。

本次将临时忙碌与真正不可用状态分开：

- 所有页面的操作按钮、开关、选择框在临时忙碌时保持原样式，由统一输入拦截层阻止重复操作。
- 按钮通过受保护的 `triggered` 信号执行动作，避免程序化或辅助操作在忙碌时重复触发。键盘按下后才进入忙碌的情况也不会执行动作或留下按下状态。
- 保留 Tab 导航与真正不可用状态，例如请求暂停、表单无效、未添加账号。
- 主连接按钮只在用户主动重连时显示进度，自动检测不改按钮文字。
- 账号按钮和下拉内容只在实际内容改变后更新，普通刷新保留原控件和焦点。
- 后台检测、认证、串行执行器和请求失败保护的规则保持原有实现。

## 自动检查

- 桌面单元测试：108 项通过，包含自动检查、只读刷新与主动重连的按钮进度区分。
- 真实 QML 交互检查：四个页面分别连续切换四轮忙碌/空闲；核对全部操作按钮的身份、颜色、文字、尺寸和焦点边框不变。
- 鼠标悬停及键盘聚焦时保持外观；忙碌时鼠标、空格激活被拦截；空闲时操作恢复。按下空格后进入忙碌再释放，不触发动作或留下按下状态。
- 账号按钮在状态通知后保留实例和焦点；原账号编辑、复制邮箱、更新入口、设备、诊断、深浅色和窗口宽度检查继续执行。
- 构建执行源码 QML、交互检查、PyInstaller、移除开发 PATH 后的独立 EXE 检查、安装器及完整免安装 ZIP 打包。具体结果保存在本地 `desktop/screenshots/v0.3-ui/ui-report.json`、`desktop/.cache/clean-runtime-report.json` 与构建日志。

## 使用与限制

交付 `OUNet-0.3.2-Setup-x64.exe`、`OUNet-0.3.2-Windows-x64-portable.zip` 及对应 SHA-256。先从托盘完全退出旧程序，再覆盖安装或替换完整免安装目录。

没有覆盖或卸载用户现有安装，也没有提交真实校园认证。真实显示器与网卡环境的人工试用仍需用户确认。此前 Android 1.3.5 和 Windows 0.3.1 的草稿不因本次修复自动公开或替换。
