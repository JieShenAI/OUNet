## 1. 本次更新的目标与范围

将面向小米首轮验证的应用升级为采用统一 Android 网络能力、覆盖小米/Redmi、iQOO、vivo、OPPO 的校园网助手。这里的“其他操作系统”指这些品牌的 Android 系统及其定制系统，不扩展为 iOS 或不兼容 Android APK 的系统。

| 用户需求 | 本版设计结果 |
| --- | --- |
| 自动扫描获取真实 Wi-Fi 名称 | 启动和网络变化时自动读取当前连接的真实 SSID；提供附近网络扫描与目标下拉选择；展示权限、扫描时间及失败原因 |
| 保存与切换多个校园网账号 | 本机保存多份加密凭据，首页用下拉框切换；支持新增、编辑、删除与默认选中记忆 |
| 间隔单位为秒 | 界面、校验、存储和调度统一使用秒；建议 10–3600 秒，默认 120 秒，快捷值 30/60/120 秒 |
| 启动后立即检测网络 | 首屏立即刷新网络状态并启动异步检测，不等待周期、不要求先填写账号、不要求先开启自动监测 |
| 小米以外品牌兼容 | 按 Android API 版本处理权限及网络接口，按品牌展示后台设置引导，分别完成真机验收 |

本版保留一个用户确认的目标 SSID，可供多个账号共用。暂不增加多个目标网络的优先级、账号自动轮换、强制下线旧会话、云同步或自动缴费。账号切换表示“今后需要认证时使用此账号”，不是切换学校服务器上的现有在线会话。

## 2. 已有实现与差距

以下结论来自现有源码审查，不能理解为现有项目已经只能在小米运行。

| 现状证据 | 对更新的影响 |
| --- | --- |
| `app/build.gradle`：原生 Java、minSdk 28、compileSdk/targetSdk 35、1.0.0 | 保留 Android 9 起的基础架构；本次功能改造先不捆绑 SDK/框架升级 |
| `WifiAccess.selected()`：只按已填目标名匹配已连接的 Wi-Fi Network | 已有真实 SSID 读取基础，但没有独立的当前连接展示、附近扫描和选择器 |
| `MainActivity`：手工输入 SSID、账号、密码；`AppStore` 只有单份凭据 | 需要账号集合、选择状态与管理界面，不能只给现有账号输入框加一个下拉框 |
| `AppStore.intervalMinutes()` 和 `save()`：默认 2、范围 2–60 | 需要新秒字段及一次性单位迁移，旧 2 分钟必须变为 120 秒 |
| `MonitorService`：30 秒心跳、3 秒事件延迟；`LoginEngine`：固定 60 秒自动检查防抖 | 仅修改标签不能实现 10/30 秒检测，需重做调度并分离认证节流 |
| `onCreate()` 只刷新已保存状态；`onResume()` 仅在监测已启用时尝试恢复服务 | 自动监测关闭时，打开应用不会立即检查；首次无账号时也不能正确检测 |
| `LoginEngine.check()` 先检查账号配置，再检查网络 | 需要把只读检测从登录引擎中拆出，让“网络是否可用”独立于账号 |
| `MainActivity`、`BootReceiver` 中有 HyperOS 专属引导文案 | 改为通用入口与品牌指导，核心认证协议不按手机品牌分叉 |
| 已有 Wi-Fi 绑定请求、Keystore AES-GCM、三次失败保护与单元测试 | 继续复用，并将它们列为更新的回归验收项 |

## 3. 界面与交互设计

延续现有青绿色主色、简洁卡片和原生 Android 控件。首页按“网络状态 → 当前账号 → 自动监测”排列，权限和记录收在次级入口，避免每次使用都要穿过一整屏授权按钮。

### 3.1 首页结构

```text
海大网络助手                         设置

校园 Wi-Fi 可上网 / 待认证 / 正在检测…
本机网络：移动数据可用（或 Wi-Fi / 无网络）
当前 Wi-Fi：系统读取到的真实名称
目标 Wi-Fi：已确认的名称 / 尚未选择
最近检测：17:30:12                   刷新
                         [检查并连接]

校园网账号
[ 我的账号 · 20****01             ▾ ]
密码已加密保存                 管理账号

自动监测                         [开关]
检查间隔                 [ 120 ] 秒
[30 秒] [60 秒] [120 秒]       保存间隔
最近检查 / 预计下次检查 / 失败保护状态

Wi-Fi 与目标设置   后台设置与权限   运行记录
```

“刷新”只检测，不提交凭据；“检查并连接”在符合目标网络、账号和失败保护条件时才可能认证。已联网时点击后不重复登录。当前 Wi-Fi 为系统观察值，目标 Wi-Fi 为用户保存值，两者始终分开显示。

### 3.2 Wi-Fi 与目标设置

- 页面打开后自动读取已连接 Wi-Fi；有权限时自动请求一次附近扫描，保留“重新扫描”入口。
- 列表标出“当前已连接”，显示可用名称、信号和扫描时间。相同 SSID 的多个接入点按名称合并；内部保留当前 Network 身份，不能用扫描列表推断请求应走哪条连接。
- 选择名称后点击“设为目标”才保存；读取或扫描结果不自动改写原目标，不将附近信号最强的网络自动视为校园网。
- 新安装不预填个人 SSID。已有安装保留原来明确保存的目标；只有旧版默认值、没有完成配置的安装仍要求用户确认。
- 扫描缓存显示“上次扫描”，不能冒充实时结果；受限、超时、定位关闭或无结果时分别解释，不把 `<unknown ssid>` 当作真实名称。
- 隐藏网络或未出现在列表中的目标允许手工输入，但自动认证前仍须从已连接 Network 确认实际 SSID；手工名称不能绕过权限校验。
- 本版由用户通过系统设置连接 Wi-Fi，不自动打开 Wi-Fi、不接管系统选网，也不要求输入路由器密码。

### 3.3 多账号管理

| 操作 | 设计行为 |
| --- | --- |
| 新增 | 输入备注、校园网账号、密码；首次密码必填；保存成功后可设为当前账号 |
| 下拉切换 | 选项展示备注和脱敏账号；立即保存选中 ID，回到首页可见；不把密码解密回填到输入框 |
| 编辑 | 账号名只读，允许改备注与密码；改账号名按新增处理，减少沿用错误密码的歧义 |
| 密码留空 | 仅在编辑同一 accountId 时保留该账号已有密文；新增时不能复用任何其他账号的密码 |
| 重复账号 | 规范化账号前后空白后识别重复，转到编辑已有账号；密码按原始文本保存，不裁剪 |
| 删除 | 明确提示删除哪个账号；删除当前账号后关闭自动监测并要求重新选择，保留只读检查，避免暗中切到另一账号 |
| 执行中切换/编辑/删除 | 使旧运行失效并取消后续步骤，随后只读重检；已发出的服务器请求无法撤回，界面不宣称撤销成功 |
| 已在线时切换 | 提示“已选择，下一次需要认证时生效；当前在线会话保持”；不注销或强制认证 |
| 没有账号 | 继续显示网络和扫描状态；“检查并连接”引导新增账号；不影响只读刷新 |

实际 APK 可输入账号密码；规划原型只使用虚构、脱敏条目，不收集真实凭据。

### 3.4 后台与权限页

展示系统版本、识别到的品牌、精确位置、系统定位、通知、后台识别能力、电池优化状态和监测服务状态。支持手动切换品牌指导；iQOO 和 vivo 的后台行为分别验收，不能因为同属 OriginOS 就直接标为均已通过。

状态使用“已授权 / 未授权 / 无法自动确认 / 待实机验证”。能打开设置页不代表设置已开启；自启动和厂商白名单若无公开查询接口，就显示操作说明与验证方法。

## 4. 启动检测与网络状态模型

### 4.1 立即检测的定义

1. `onCreate/onResume` 先输出“正在检测”及当前系统网络快照，禁止把上次的“网络正常”作为本轮结果。
2. 目标为首屏可见后 **1 秒内发起**异步只读检测；这是发起时限，DNS、探测和认证不承诺瞬间完成。主线程不执行网络 I/O。
3. 即使未保存账号、自动监测关闭或 SSID 权限未授予，仍显示本机连接类型、系统是否验证联网、Wi-Fi 是否存在及缺少的条件。
4. SSID 可确认时，对目标 Wi-Fi 的检测绑定该 Network；本机默认网络状态只作为另一项信息。移动数据可用不能证明校园 Wi-Fi 已恢复。
5. 冷启动、后台回前台、授权返回、网络变化触发同一检测协调器；同一轮合并，近期已有结果则刷新系统快照并按需补检，避免权限页往返造成重复请求。
6. 已开启监测时，立即检查结果可交给认证流程；关闭监测时，启动检测保持只读，需用户点击“检查并连接”才允许认证。

### 4.2 展示状态

| 状态 | 判断与行为 |
| --- | --- |
| 无可用网络 / Wi-Fi 关闭 | 展示明确原因与系统 Wi-Fi 入口，不提交账号 |
| 仅移动数据可用 | 显示本机可上网，同时显示校园 Wi-Fi 未连接，不重置校园网失败保护 |
| Wi-Fi 存在但名称受限 | 显示权限/定位检查，不猜测名称、不认证 |
| 当前不是目标 Wi-Fi | 展示当前与目标的差异，只读待命 |
| 目标 Wi-Fi 可上网 | 绑定 Wi-Fi 的探测成功；允许清除失败保护，本轮不登录 |
| 探测未通过 / 结果不确定 | 区分超时、DNS、重定向与系统认证提示；失败本身不等于已经确定要登录 |
| 识别到学校认证并需要登录 | 目标身份确认、监测开启或用户主动操作、凭据可读、预算允许后，进入固定学校域名的认证流程 |
| 认证中 / 恢复验证中 | 公开进度，合并其它触发；不并发提交 |
| 认证暂停 | 显示全局保护与重置入口，保留外网探测，停止所有学校认证请求 |

`NET_CAPABILITY_VALIDATED`、`CAPTIVE_PORTAL` 是系统线索；不能仅用 `INTERNET` 能力或“拿到 IP”宣告外网可用。扫描结果也不能证明已经连接。Network 断开后重新连接，即使 SSID 相同，也视为新连接。[Android 网络状态说明](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)

外网探测保留现有双端点的预期内容校验，并增加结构化结果和整轮超时。只有学校固定 HTTPS 域名的页面/配置满足现有协议校验，才允许提交密码；任意重定向或其它校园网 Portal 都不作为可信认证入口。学校页面、脚本和配置的读取仍纳入三次保护，不增加未计数的“后台识别认证”请求。

## 5. Wi-Fi 获取和品牌兼容方案

### 5.1 接口与权限按版本处理

| Android 范围 | 主要策略与验收重点 |
| --- | --- |
| 9 / API 28 | 单 Wi-Fi 下兼容 `WifiManager.getConnectionInfo()`；精确位置与定位开关；扫描权限 |
| 10–11 / API 29–30 | 优先读取每个 Network 的 `WifiInfo`；仅单连接且映射明确时使用旧接口回退；后台位置分步申请 |
| 12–12L / API 31–32 | 使用带 `FLAG_INCLUDE_LOCATION_INFO` 的回调获得未脱敏的连接信息；处理仅近似位置授权 |
| 13 / API 33 | 保留扫描所需精确位置；仅在实际使用需要的 API 时请求附近 Wi-Fi 权限；通知权限单独处理 |
| 14–15 / API 34–35 | 校验前台服务类型、权限、启动入口、开机恢复与应用更新恢复 |
| 16 及更新版本 | 列入兼容实测范围；实施时核验当时稳定版本的行为变化，不因 APK 可安装就标为兼容通过 |

实现使用公共 API 和运行时能力检查，不依赖手机型号白名单。Android 12 起，回调即使已有权限也可能默认删除位置信息，必须结合上述标志、授权和系统定位处理。[NetworkCallback 官方说明](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback#FLAG_INCLUDE_LOCATION_INFO)

主动扫描新增 `CHANGE_WIFI_STATE` 普通权限；`getScanResults/startScan` 在 Android 13 及以上仍有精确位置要求，不能把 `ACCESS_FINE_LOCATION` 简单限制到 API 32 或仅以“附近设备”替代。扫描只在界面需要时发起，绝不随 10 秒网络检测周期执行。前台扫描有频率限制，后台更严格；通过缓存时间和被动扫描完成通知更新列表。[Wi-Fi 权限](https://developer.android.com/develop/connectivity/wifi/wifi-permissions)、[扫描限制](https://developer.android.com/develop/connectivity/wifi/wifi-scan)

授权流程分层：基础网络快照 → 用户使用名称/扫描时申请使用期间精确位置 → 开启后台监测时解释后台 SSID 识别并分步申请后台位置 → 单独说明通知与省电设置。拒绝后台位置不影响前台检测；后台无法确认目标身份时暂停认证。拒绝通知时说明监测通知的可见性限制，不把通知授权当作检测网络的必要条件。

### 5.2 品牌适配

| 品牌/系统族 | 引导重点 | 验证状态 |
| --- | --- | --- |
| 小米 / Redmi，MIUI / HyperOS | 后台自启动、应用省电策略、必要时最近任务保留 | 现有面向小米的代码也要重新验收，不能沿用未记录的通过结论 |
| iQOO，OriginOS / 部分海外系统 | 自启动、后台耗电管理、后台联网，按实际系统提供说明 | 待真机验证 |
| vivo，OriginOS / Funtouch OS | 自启动、后台耗电管理、最近任务保留 | 待真机验证 |
| OPPO，ColorOS | 自启动、应用电池/后台活动管理、最近任务保留 | 待真机验证 |
| 其它 Android | 应用详情、位置权限、电池优化、通知等系统通用入口 | 通用能力支持，未声称全部品牌已经验证 |

厂商文档可确认存在不同的自启动/后台管理入口，但菜单文字因版本和地区变化：参考[小米适配建议](https://dev.mi.com/docs/appsmarket/technical_docs/adaptation_FAQ/)、[vivo 客服说明](https://kefu.vivo.com.cn/robot/imgmsgData/2616a9cd7cd64a5083a264d16e5767da/index_1.html)、[OPPO Phone Manager 说明](https://support.oppo.com/co/answer/?aid=neu119)。iQOO 先复用 vivo 系统族的引导结构，具体路径作为待实机确认项，不能据此认定兼容已通过。

优先跳转公开的应用详情、定位、Wi-Fi、电池优化和通知设置。若后续加入厂商专属入口，必须确认可解析、捕获异常并回退通用页面；不将某个私有 Activity 类名作为功能依赖，也不把系统安全防护关闭作为安装要求。

### 5.3 后台执行边界

沿用用户主动开启的前台服务和可停止的监测通知。`specialUse` 仍需按实际用途复核，不是后台权限或定时执行豁免；上架 Google Play 还涉及用途审核。[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)

Android 12 起后台启动前台服务存在限制；开机/更新恢复失败须记录可读原因，在下次用户打开时恢复或引导，不能静默显示“正在运行”。用户强制停止应用后不承诺自动复活。[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)

秒是配置和运行中的调度单位，不代表锁屏深度休眠时严格准点。Doze 及厂商省电可推迟 CPU 和网络执行；界面显示实际上次时间，并将下次时间标为“预计”。本版不引入精确闹钟、持续唤醒锁或辅助进程保活。[Doze 官方说明](https://developer.android.com/training/monitoring-device-state/doze-standby)

## 6. 秒级调度与并发规则

| 项目 | 拟定规则 |
| --- | --- |
| 检测间隔 | 整数 10–3600 秒；默认 120；非法、空、小数、溢出输入就地提示，不静默纠正 |
| 单位迁移 | `interval_minutes × 60`，标记成功后不再重复乘；原 60 分钟为 3600 秒 |
| 周期机制 | 替换固定 30 秒心跳，使用可取消的单次调度；以 monotonic clock 计算到期，保存设置后重排 |
| 检测耗时超过间隔 | 同时最多一轮；短轮次按开始时间计算下一次到期，若上一轮已超期，则完成后再等一个间隔；不积压错过的周期 |
| 事件防抖 | Wi-Fi 事件合并约 2 秒，等连接信息完整；连接丢失立即更新状态并使旧轮失效 |
| 启动/手动刷新 | 不等待周期或旧 60 秒门槛；合并正在执行的检测；手动操作不能绕过认证保护 |
| 认证节流 | 与探测周期分离：两轮认证开始至少相隔 60 秒；结合已持久化的尝试记录判断，重启/切换不绕过；10 秒检测不等于每 10 秒提交密码 |
| 调整间隔 | 只改变后续检测计划；不清空失败保护、不在保存时立即发起认证 |
| 关闭监测 | 取消后续周期和未发出的认证步骤，释放后台监听；首页保留只读检测 |
| 执行时限 | 拟设只读外网探测总预算 8 秒、含认证与恢复复查的整轮总预算 60 秒；按剩余预算限制请求，避免多个逐请求超时叠加 |

认证流程固定一份不可变快照：`accountId + credentialRevision + targetSsid + configGeneration + Network`。提交前重新核验 Network 仍有效、真实名称仍匹配、配置代数未变和监测/手动授权仍有效。切换账号或目标后取消旧任务，忽略旧结果，禁止账号和密码分别读取导致混用。

保留现有**本机所有账号共享**的“10 分钟内三轮未恢复则暂停”保护。切换、编辑、删除或新增账号、重启应用以及变更间隔均不能自动清零。暂停不在十分钟后自行解禁；只有绑定目标 Wi-Fi 的外网探测成功或用户明确重置才解除。预算在首次学校请求之前持久化，记录异常则停止认证。

## 7. 数据模型与升级迁移

在现有 `AppStore` 上增加小规模账号集合，不为本次更新引入数据库或重写为其它语言。

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 新配置版本 2，迁移完成标记与新配置同一次原子提交 |
| `accounts` | `accountId(UUID)`、备注、账号、该账号专属密文/IV、`credentialRevision` |
| `active_account_id` | 选中账号 ID，不能使用数组下标，删除和排序不能误选 |
| `target_ssid / target_confirmed` | 用户确认的目标，独立于账号；保留合法 SSID 内容，不一概 trim SSID |
| `interval_seconds` | 秒整数，不混存分钟 |
| `enabled` | 用户期望的监测开关；实际服务/权限状态另行显示 |
| `retry` | 延用现有全局保护记录，不因配置版本变化重置 |

继续使用 Android Keystore AES-GCM，保存每个账号时生成独立 IV；密文、账号归属和活动账号一起校验。延用现有密钥及兼容的密文格式，避免覆盖升级后无法解密。备份与设备迁移仍关闭，日志不写凭据、完整认证 URL 或扫描列表。

迁移顺序：读取旧配置并校验 → 将旧单账号的现有密文/IV 复制到一个固定迁移 ID 的账号 → 迁移目标、开关和分钟值 → 校验新集合引用和失败记录 → 一次提交新配置及版本标记 → 成功后使用新配置。旧配置只有部分字段时不凭空生成可用账号；没有旧间隔的全新安装使用 120 秒。

迁移须幂等，提交失败保留旧数据并提示，不生成明文备份、不清除失败记录。保留旧加密字段用于升级核验，确认迁移后再按策略清理；不向界面显示“迁移完成”直到成功落盘。任一密码不可读时只要求修复对应账号，仍可查看网络。

## 10. 验收矩阵

### 10.1 功能与异常

| 验收场景 | 通过标准 |
| --- | --- |
| 冷启动，未配账号、监测关闭 | 首屏 1 秒内开始检测；显示本机网络与缺少条件，不提交凭据 |
| 冷启动，已配置且开启监测 | 不等待周期；可用时不登录，需要认证时按同一保护执行 |
| Wi-Fi 未认证但移动数据可用 | 本机和校园网状态分开；所有认证/复查仍走 Wi-Fi，蜂窝网络不能清零保护 |
| 真实 SSID / 中文、引号、前后空格、长名称 | 正确显示和精确匹配；只剥离 API 包裹的成对引号，不破坏真实字符 |
| 精确位置拒绝、仅近似位置、定位关闭、后台位置拒绝 | 分别显示原因；基础网络检测仍可用；不猜测目标、不错误发送凭据 |
| 附近扫描成功、受限、空列表、缓存、隐藏 SSID | 列表与时间正确；目标只在用户确认后保存；不随秒周期重复扫描 |
| 双 Wi-Fi、VPN、智能切换、Wi-Fi/蜂窝并存 | 能明确映射目标才认证；歧义时停止并说明；断网后的旧 Network 不复用 |
| 保存至少 3 个账号，重启后下拉切换 | 选中项持久化；凭据与 ID 一一对应；未选中的账号不参与认证 |
| 新增空密码 / 编辑留空 / 重复账号 / 删除当前账号 | 无跨账号沿用；校验和删除行为符合设计；不暗中改用另一个账号 |
| 认证过程中切换账号、改密码、改目标或关闭监测 | 未发出的旧提交被取消，旧结果不覆盖新状态；无账号密码混合快照 |
| 旧版覆盖升级 | 原账号密文可读，2→120、60→3600；目标、开关与暂停状态保留；迁移重复/中断不损坏 |
| 间隔 10/30/60/120/3600、非法与溢出值 | 亮屏且进程可运行时，短探测开始间距符合设置，允许预设调度误差；长轮次不积压；保存实时生效 |
| 网络事件风暴 + 手动点击 + 周期同时到达 | 同时最多一轮；周期不受旧 60 秒检测门槛干扰；认证仍有独立节流 |
| 三轮失败、切换/删除/新增账号、重启 | 全局暂停保持；所有学校请求停止；仅目标 Wi-Fi 恢复或明确重置可解除 |
| 超时、学校协议变化、密码解密失败、配置/保护损坏 | 有截止时间和可读提示；不绕过证书、预算、目标确认或错误密文继续发送 |
