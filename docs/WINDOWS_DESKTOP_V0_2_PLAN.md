# Windows desktop v0.2 更新设计与实施规划

日期：2026-10-22。状态：**已实现为 Windows 0.2.0 测试版**，验证范围见 [实施记录](WINDOWS_VERIFICATION.md)。下文保留设计契约；“本轮只做设计”描述此前的规划阶段，实现阶段状态见第 10 节。

本方案以现有 Windows 0.1.0 的 PySide6 / QML 实现为基础，覆盖本次七项更新。可离线审阅的[新版交互原型](../design/windows/desktop-v0.2.html)只使用模拟数据，不发认证请求。旧版[产品规划](WINDOWS_PRODUCT_PLAN.md)与[界面规范](../design/windows/DESIGN.md)作为 v0.1 历史保留；其中单账号、连接记录页、十分钟三轮、两分钟认证冷却等约定，由本文覆盖。

用户已确认失败口径：**按实际 HTTP 请求连续失败计数，成功请求清零；外网探测发现需要认证不算失败；第三次后停止自动网络请求，等待手动重试。**

## 1. 更新范围与对应方案

| 需求 | 更新后的行为 |
| --- | --- |
| 打开即检测，断网即登录 | 首个后台网络任务就是外网检测；不等 Wi-Fi 枚举或旧任务扫描。无网时在同一次流程内接续恢复，不等待周期定时器。 |
| 概览顶部六项信息 | 用“当前校园网会话”替换大号“网络已连接”，展示账号、上线时间、源 IP、源 IPv6、源 MAC、移动端标识。连通性使用小号状态标签。 |
| Wi-Fi 与多账号 | 账号页及首次设置均先选 Wi-Fi，再选校园网账号；删除 SSID / Windows 配置名称文本框。每个账号分别记住加密密码，已保存时显示固定星号。 |
| 秒级自定义间隔 | 默认 120 秒，支持任意受支持范围内的正整数秒，最小 1 秒。前一轮结束后再等待设定秒数，绝不并发补发。 |
| 本次开机恢复明细 | 概览显示恢复总次数与逐条时间、恢复方式、耗时；同一次故障只计一次，同次开机重开应用保留。 |
| 新连续失败规则 | 删除常驻“失败保护 待命中”卡和旧十分钟窗口。实际请求连续失败三次后，显示暂停横幅并阻止剩余及后续自动请求。 |
| 删除连接记录 | 删除侧栏入口、独立页面、概览跳转；恢复明细放在概览，排障日志导出放在帮助页。 |

本轮不改变 Android 行为，不修改真实账号、自启、Wi-Fi 或任务计划，不制作新的安装包。后续实现仅对共享 CLI 做桌面接管兼容所需的最小调整，不把 Android / 独立 CLI 顺带改为新策略。

## 3. 页面与交互设计

### 3.1 导航

保留“连接概览 / 账号与网络 / 偏好设置 / 帮助与关于”四个入口。QML 后续改用命名路由，避免删除数字页码后“设置”跳到“帮助”。

### 3.2 连接概览

页面顺序为：会话信息 → 自动守护与检查摘要 → 本次开机恢复明细。暂停横幅仅在请求暂停时插入，不为正常状态预留空卡。

```text
连接概览                              [检查并连接]
┌ 当前校园网会话 ──────────────────────────┐
│ [外网可用 / 正在检测 / 正在恢复 / 暂未确认]  │
│ 账号           上线时间          移动端标识 │
│ 源 IP          源 IPv6           源 MAC    │
│ 来自 xha.ouc.edu.cn · 更新于 HH:mm:ss      │
└─────────────────────────────────────────┘
┌ 自动守护 [开关] ─────────────────────────┐
│ 检查完成后等待 120 秒 · 上次检查 HH:mm:ss   │
│ 当前 Wi-Fi · 用于下次恢复的账号             │
└─────────────────────────────────────────┘
本次开机已恢复 2 次              开机时间 …
2026-10-22 10:24:18  校园网认证恢复  耗时 …
2026-10-22 08:15:06  Wi-Fi 重连恢复  耗时 …
```

- 六字段在宽窗口三列两行，窄窗口两列或单列；完整 IPv6 可换行，不静默截断。正文使用可选择的纯文本，不渲染远端 HTML。
- “账号”取网站当前会话，不取账号下拉当前选项。切换用于恢复的账号，不立即注销已有会话；可以同时显示“当前在线：A / 下次恢复使用：B”。
- 首次获取显示“正在获取”；字段缺失显示“页面未提供”；完全取不到显示“暂未获取”。失败时有旧值则明确标“上次获取的信息 / 当前未刷新”及采集时间。
- 网络断开后旧会话不再作为当前在线事实；顶部可保留旧快照，但必须显示“上次会话”。
- 外网可用但取不到校园会话时显示“外网可用，暂未取得校园网会话”，不把校园会话查询失败改写为“电脑断网”。
- 正常状态不显示失败保护标题、盾牌计数或“待命中”。第 1、2 次请求失败仅在检查说明中显示错误与重试状态。
- 第 3 次显示：“连续 3 次网络请求失败，已停止自动网络请求。”附发生时间、最近错误和“手动重试”。保留上次网络结论与时间，不继续宣称实时在线。

### 3.3 账号与网络

控件顺序固定为：

1. **校园 Wi-Fi**：一个下拉框，显示 Wi-Fi 名称；附“刷新”和“打开 Windows 网络设置”。不提供 SSID / profile 的自由文本输入。
2. **用于自动恢复的账号**：下拉选择已保存账号；提供添加、保存修改、删除。选中后用于下一次需要登录的流程，不轮流尝试其他账号。
3. **校园网密码**：已保存时显示固定 `********` 占位；新账号显示“请输入密码”。已有在线会话但软件未保存该账号密码时，明确显示“密码未保存”，不能仅根据在线状态伪造已保存标识。
4. 自动连接所选 Wi-Fi 等原有偏好，以及配置保存结果。

下拉内部绑定 `{interface_id, profile_name, ssid}`；同名 Wi-Fi 使用网卡/配置摘要区分，配置信息不再要求用户输入。仅列 Windows 可用的已保存配置；未保存网络先到 Windows 手动连接一次。没有无线网卡、WLAN 关闭、列表权限失败时给出具体原因，但外网检测仍可运行。

密码使用 `has_saved_password` 与 `password_action=keep|replace` 明确表达意图。输入控件的真实值为空，星号只是占位；留空并保存旧账号表示保留，输入新内容表示替换。切换账号前如有未保存修改，提示保存或放弃；检查中暂不更换活动配置。真实密码不进入 QML 状态映射、HTML 原型或日志。

账号删除与凭据文件更新同一事务完成；删除活动账号后选择另一个有效账号，若无账号则停止后续自动认证。删除软件中的账号不注销网站当前会话。

### 3.4 偏好与帮助

- 间隔采用数字输入框，单位固定“秒”，默认 120，最小 1，快捷值可用 1 / 5 / 30 / 120。拒绝 0、负数、NaN、小数和超出定时器能力的数值，并显示原因。
- 文案为“每轮检查完成后等待 N 秒”，避免将包含请求耗时的实际周期写成精确每 N 秒。
- 当最近整轮耗时 `D > N`，显示：“设置间隔 N 秒，最近一轮耗时 D 秒；本轮完成后再等待 N 秒，不会并发请求。”提示常驻于检查摘要/间隔控件附近，去重，不反复弹通知；耗时恢复正常后清除。
- 删除旧“十分钟三轮”和“重置失败保护”设置组。新规则在帮助说明，手动重试只在实际暂停时出现。
- 帮助页保留脱敏排障导出；不重新引入“连接记录”导航或全部记录页。

## 4. 启动、会话获取与调度

### 4.1 启动优先级

```text
加载本地配置 + 取得单实例锁 + 读取请求暂停状态
  ├─ 已因三次请求失败暂停 → 展示暂停原因，等待手动重试
  └─ 可请求 → 首个后台任务立即检测外网
       ├─ 有网 → 不登录；获取校园网会话信息
       └─ 无网 → 检查必要认证条件 → 同轮连接 Wi-Fi / 登录 → 复查
                  └─ 验证恢复 → 记录恢复事件 → 获取校园网会话信息
后台再加载 Wi-Fi 选项、订阅网络事件、刷新非必要的系统信息
```

“立即”指不等待 120 秒间隔、不等待非必要枚举；DNS、超时和学校服务响应时间仍决定检测完成时间。不能跳过外网检测直接提交密码。

每次新建应用进程均执行一次启动检查；重复启动只激活已有窗口，不另建任务。“自动守护”开关控制后续周期检测；关闭时仍执行此次启动单次检查与必要恢复，此语义在设置旁说明。已触发请求暂停、凭据缺失、旧入口未完成接管等条件仍阻止认证。首次安装尚无账号时仍检测外网，提示配置；保存有效配置后立即安排一次检查。

Wi-Fi 初始化失败不挡有线外网检测；已联网不切 Wi-Fi、不重新认证。离线且所选 Wi-Fi 已连接时直接进入认证；未连接时遵循自动连接所选 Wi-Fi 的设置，不能发出不具备网络条件的登录请求。

### 4.2 何时获取六项在线信息

- 每次应用启动的首次联网检测通过后获取一次，覆盖第一次安装后已联网的情况。
- 每次已观测的断网恢复并经外网验证通过后获取一次。
- 用户点击“刷新会话信息”时获取；网络/路由变化后将已有快照标旧，并合并一次刷新。
- 普通在线周期检测不每次抓取会话详情，减少无用请求；查询失败不进入紧密循环。
- 查询走相同请求门闩与串行执行器，暂停期间禁止自动和普通刷新入口发出请求，改为引导“手动重试”。

**来源核验状态：**规划阶段未能访问站点；实施阶段已成功只读核实 [校园认证站点](https://xha.ouc.edu.cn/)的脚本、当前状态与在线记录接口，并完成六字段映射和当前设备匹配。见 [门户协议核验记录](WINDOWS_PORTAL_PROTOCOL.md)。未以登录上下文或本机网卡推测会话信息。

实施第一步需在校园网内只读检查网页及其公开脚本，确认页面实际调用的状态查询，再建立最小请求与脱敏测试样本。来源优先级是：网站已有只读状态接口 → 网站实际页面字段解析；不猜接口、不执行下载来的 JavaScript、不额外提交账号密码读取状态。

源 IP / IPv6 / MAC 保留网站含义，不用本机网卡地址或第三方“查公网 IP”服务替代。上线时间不使用应用启动时间；移动端标识不从登录参数 `terminal_type=1` 推测。多条会话时只按站点明确的当前设备依据匹配，不随便取第一条；无法唯一匹配时显示未确认。

### 4.3 串行与间隔

采用现有执行器扩展为“一个完整网络工作流在执行，最多一个待处理标记”：

- 启动、周期、手动、网络事件、会话刷新均进入统一入口。任意时刻最多一个 HTTP 请求在途，且不会并行开展第二套恢复流程。
- 用单次定时器：一轮全部结束，再等待设置的 N 秒。去除 desktop 固定 120 秒认证冷却；不保留隐藏的 60 秒或 10 秒下限。
- 执行中停止周期计时；重复手动点击不积累任务，网络事件只保留一个 pending 并合并意图。结束后最多消费一次，不追补漏掉的历史 tick。
- 网络变动沿用稳定等待与合并机制；启动首次检测不走 5 秒事件防抖。定时器、pending 同时到期时仅产生一个任务。
- 请求暂停、用户关闭守护、退出时清理相应 pending，不能在回调中把已取消的自动任务重新排上。
- 调度与耗时用单调时钟；显示时间保存带时区时间戳。调系统时间不改变间隔或三连败计数。

## 5. 按实际请求计数的失败策略

### 5.1 计数语义

计数对象是应用实际发出的 HTTP 请求，包括外网探测、校园认证与会话查询；不是按钮点击次数，也不是认证流程轮数。一个流程可能有多个 GET，因此必须在每次发送前检查暂停状态，在每次请求完成后更新结果。

| 请求结果 | 失败计数 | 网络/业务状态 |
| --- | --- | --- |
| DNS、连接、TLS、超时异常 | 加 1 | 未获得有效响应；保留错误阶段 |
| HTTP 服务异常，或门户接口响应不符合已核实结构 | 加 1 | 请求失败，不能伪装成登录失败轮次 |
| 有效成功响应 | 清零 | 不代表一定有外网，需要按探测内容另判 |
| 外网探测收到门户重定向/认证页 | 不加失败；有效门户响应按成功收到响应处理 | 说明外网需认证，进入恢复；绝不因 HTTP 200 就判在线 |
| 门户返回结构有效的账号密码错误等业务拒绝 | 不算传输失败，成功响应清零 | 显示业务原因；明确凭据无效时等待修改或换账号，不无限重复相同凭据 |
| Wi-Fi 未连接、用户取消、配置缺失、本地存储错误 | 不计 HTTP 失败 | 展示对应处理原因，不能混入网络请求计数 |

例如“失败 → 失败 → 成功 → 失败”的结果是 1 次；间隔是否超过十分钟不影响计数。认证页成功会打断登录请求失败的连续性，这是用户选择“实际请求”口径的结果，不再额外叠加旧三轮规则。外网有无、请求是否成功、凭据是否被接受是三个不同结论。

每个请求必须完整读取响应并完成对应类型的结构校验后，只结算一次。不能收到 HTTP 200 就先清零，再把 JSON / 字段解析失败计成一次新失败，否则连续无效响应永远到不了三次。明确关闭请求库自动重试与自动重定向，避免库内部发送的额外请求绕过门闩。若必须跟随站点正常跳转，每一跳都作为一次显式受控请求；含凭据请求不允许跨到未核实的主机。

### 5.2 第三次失败之后

状态为 `ready → failure_1 → failure_2 → paused`；一次有效成功立即回到 `ready`。第 3 次失败结算时先原子保存暂停状态，再结束当前任务：

- 禁止当前流程剩余的第二探测、后续配置、登录、认证后复查及会话详情请求。
- 停止周期定时器，取消网络事件触发和待执行标记，托盘与普通刷新不得绕过；不保留旧版“暂停后继续只检查外网”。
- 页面切换、开关守护、修改密码、切换账号、重新打开软件都不自动清零。新规则不依赖十分钟窗口；请求暂停在应用重启后仍保留。
- 不产生自动恢复倒计时；本地 WLAN 事件本身可接收，但不能因此试发 HTTP。暂停后软件无法自动确认外网复通，需要用户操作后才能确认。

“手动重试”进入一次串行试探：先放行一个受控请求；失败则立即回到暂停，不发送本轮后续请求。收到有效响应后关闭暂停、清零，再按正常流程判断是否需要登录并完成这一轮；之后只有守护开启才重新安排周期检查。重试期间按钮禁用，不额外开启第二个请求。凭据错误按独立业务原因处理，不用网络断路提示替代。

## 6. 开机以来的恢复统计

新增独立恢复台账，不能把所有 `success` 活动日志当作“解决一次失败”。

- 首次确认为离线时创建 `outage_id`；同一离线阶段重复检测沿用该 ID。
- 应用实际执行 Wi-Fi 重连或校园认证后，经外网探测通过，写一条恢复事件；同一 `outage_id` 只能提交一次。
- 时间显示 `YYYY-MM-DD HH:mm:ss`；记录发现断网时间、确认恢复时间、恢复方式和耗时。按最近恢复倒序，可滚动/分页逐条查看本次开机全部记录。
- 首次启动即在线、普通在线检查、刷新会话成功、用户在软件外自行修好网络不增加“软件解决次数”。对因果无法确认的情况不计为软件修复。
- 认证返回成功但外网未通不计数；第三次请求失败暂停不计数。恢复已验证后会话信息查询失败，不撤销已记录的恢复。
- 同次 Windows 启动内关闭/重开应用保留，新的系统启动切换到新台账；睡眠唤醒不清零，不按午夜归零。
- 只能统计软件实际监测并参与恢复的故障；不补造软件未运行期间的记录。原 300 条通用日志不作为台账上限，滚动排障日志不能冲掉恢复明细。

`BootSessionProvider` 在 Windows 适配层统一提供启动身份/时间，初始化失败时显示“开机范围暂未确认”，保留原台账，不按应用启动时间错误清零。系统启动时间与计时器是两种用途，不用 `当前时间 - 运行时长` 的近似值充当稳定启动 ID。[Microsoft 对计时器用途的说明](https://devblogs.microsoft.com/oldnewthing/20141113-00/?p=43623)指出，GetTickCount 的绝对值不是精确定义的开机时刻。

产品口径固定为：完整重启、关机后开机（含快速启动）进入新台账；普通睡眠和完整休眠后的唤醒保留。实现以 [Win32_OperatingSystem.LastBootUpTime](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-operatingsystem) 等系统启动信息为基础，必要时结合系统启动事件区分混合启动。Microsoft 说明[快速启动会保留内核而关闭用户会话](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/distinguishing-fast-startup-from-wake-from-hibernation)，因此不能只比较内核运行时长就认定是否新一次开机。这四种边界在 P0 建立样本、P4 实机验收；无法确认时保留台账并标记范围未知。

## 7. 模块、数据与升级设计

继续使用 Python + PySide6 + QML，复用现有线程、信号和原子事务。

| 文件 / 模块 | 计划职责 |
| --- | --- |
| `desktop/ouc_desktop/controller.py` | 启动优先级、统一调度、账户命令、会话和恢复数据订阅；QML 不解析日志字符串。 |
| `desktop/ouc_desktop/engine.py` | 分离探测、恢复、会话刷新结果；所有请求接受统一客户端；恢复以 outage 为单位。 |
| 新 `desktop/ouc_desktop/request_policy.py` | HTTP 发送门闩、结构化结果、连续请求失败计数、暂停持久化与手动试探。 |
| 新 `desktop/ouc_desktop/portal_status.py` | 实际站点字段映射、校验、当前设备会话匹配；接口核实后实现。 |
| `desktop/ouc_desktop/storage.py` | Settings / CredentialStore v2、多账号事务、会话快照、RecoveryStore。 |
| `desktop/ouc_desktop/windows.py` | Wi-Fi 下拉的结构化项、正确网卡连接、BootSessionProvider。 |
| `desktop/ouc_desktop/migration.py` | v1 无损升级、旧保护语义隔离、桌面接管 marker 与锁兼容。 |
| `desktop/qml/Main.qml` 及输入组件 | 四页导航、六字段卡片、恢复明细、Wi-Fi / 账号下拉、星号占位、秒级数字输入。 |
| `desktop/ouc_desktop/app.py`、托盘 | 启动入口、暂停状态和动作同步、重复启动不新建检查。 |
| `auto_login.py` 兼容边界 | 仅在已被新 desktop 接管时识别 marker，在任何 HTTP 前停止旧检查入口，不能解析/覆盖新版请求状态。 |

内部数据契约如下，属性名不是尚未核实的网站接口属性：

```text
settings v2: active_account_id, wifi_selection, interval_seconds, monitor, ...
credentials v2 (当前用户 DPAPI): accounts[id] = {username, password}
request-state v1: consecutive_failures, paused, last_failure_at, last_error_kind
portal snapshot: account, online_since, source_ipv4, source_ipv6,
                 source_mac, mobile_identifier, fetched_at, availability
recovery ledger: boot_session_id, boot_started_at, active_outage,
                 events[{outage_id, detected_at, recovered_at, method, duration_ms}]
```

只把账号摘要和 `hasSavedPassword` 交给 UI。会话快照涉及账号和设备地址，只在当前用户本机使用；如需跨应用重启保留，沿用当前用户 DPAPI 存储，诊断导出默认去除这些值。请求错误仅保留阶段和固定类型，不写含密码的 URL、Portal 原文或原始响应。

### 升级处理

1. v1 单账号凭据无损转成一个默认账户，保留前导零；原间隔 60 / 120 / 300 的秒数直接继承。
2. v1 SSID / profile 与 Windows WLAN 实际配置匹配；不能唯一匹配时保留旧值并提示重新选择，不能误选同名网络。读取配置仅提取名称/SSID，不请求 Wi-Fi 明文密钥。[Microsoft WlanGetProfile](https://learn.microsoft.com/windows/win32/api/wlanapi/nf-wlanapi-wlangetprofile)提供 XML 配置读取及单独的明文密钥选项。
3. 使用独立 `request-state.json`，不把旧 `retry-state.json` 的认证轮次转换为 HTTP 失败数。旧文件保留作兼容备份，不再施加十分钟窗口和 120 秒冷却。
4. 若升级前已暂停，作为“旧版暂停待处理”保留，需要显式手动重试；不冒充新规则下已经发生三次 HTTP 失败。未暂停的旧轮次不导入新计数。
5. 当前 CLI 的 `runtime_paths()` 会指向 desktop 的旧保护文件，因此接管 marker 升到 `version=2, mode=desktop-managed`，并更新兼容识别。被接管的 CLI 在任何 HTTP 发送前拒绝整个旧检查入口并提示使用桌面版，不能只拦登录而继续外网探测；旧版 v1 读取器也应因不认识版本而在请求前停止。保持现有单实例/寿命锁；独立运行且未被接管的 CLI 保持原行为。
6. 账户、活动账户 ID、Wi-Fi 更新沿用 `configuration_transaction()`；中途写入失败保留 pending 标记，不使用半更新凭据。新请求暂停状态读写失败时停止请求，显示本地状态错误。
7. 旧通用日志没有 outage ID，不追溯伪造恢复次数。首次升级创建新台账，保留原日志作诊断。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 启动已联网 | 首个网络任务立即探测；零登录、零切网；随后读取六字段 |
| 启动离线且配置有效 | 不等一个周期；同轮登录并复查；通过后获取会话并计一次恢复 |
| 无配置或 WLAN 异常 | 仍可确认有线外网；没有凭据时零认证，给出配置入口 |
| 守护关闭后重开应用 | 运行一次启动检查，后续不排周期；请求暂停状态仍不被绕过 |
| 站点完整/缺字段/失效/多会话 | 展示真实来源；不伪造地址或上线时间；无法匹配时明确未确认 |
| 外网通过而站点不可达 | 网络结论与信息获取错误分开，有旧快照时注明时间和旧值 |
| 两账号交替切换 | 密码分别保留；固定星号不进入凭据；账号选择不修改当前在线身份 |
| profile 名不等于 SSID / 同名多网卡 | 下拉只选名称即可，内部使用正确 profile、SSID 与网卡 |
| 间隔 1 / 2 / 3 / 7 秒 | 均能保存生效，无隐藏 120 秒冷却；非法值有明确错误 |
| 间隔 1 秒，请求耗时 8 秒 | 最大并发 1，完成后再等 1 秒，提示过短且不刷屏；不补发历史周期 |
| 启动 / 定时 / 手动 / 网络事件同时触发 | 只有一个完整任务，最多一个 pending，暂停后 pending 不再发请求 |
| 失败→失败→成功→失败 | 连续失败数为 1，不按十分钟或认证轮次累计 |
| 外网被认证页拦截 | 进入登录流程，不误判联网，不计三连败 |
| 第三个实际请求失败 | 当前流程剩余及后续自动 HTTP 数均为 0；横幅此时才出现 |
| 暂停后切页面 / 开关守护 / 换账号 / 重开软件 | 不隐式清零，不偷偷探测或刷新会话 |
| 手动重试失败/成功 | 失败只试一个请求后回暂停；有效响应后恢复正常流程，不并发 |
| 账号密码业务拒绝 | 显示业务错误，不误算传输失败；明确无效凭据不被反复自动提交 |
| 同次断网多次检查再恢复 | 只增加一次，展示精确恢复时间；门户详情失败不影响已确认恢复 |
| 启动在线 / 外部自行恢复 / 普通刷新 | 软件解决次数不增加 |
| 同次开机重开 / 午夜 / 睡眠唤醒 | 已有恢复台账保留；新系统启动进入新台账，快速启动另行验证 |
| 通用日志超过 300 条 | 不改变本次开机恢复总数，不丢对应恢复明细 |
| v1 升级 / 中断写入 / 旧 CLI | 单账号迁移，旧暂停说明真实；事务异常不认证，旧入口不能覆盖新策略 |
| UI 回归 | 首次向导、导航、帮助、托盘均使用新规则；DPI 与长 IPv6 不溢出 |
